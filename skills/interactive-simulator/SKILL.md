# Interactive Simulator

把一个对象或现象做成可操作、可解释、可录制的实时场景。优先延续用户现有项目。新项目可从随附的已验证货轮 / 海洋基线启动；它提供可执行的效果起点，不是任意物理系统的现成实现。

## 选择复用范围

- **复现当前货轮效果**：运行下面的 scaffold，保留基线着色、镜头、参数和运动逻辑，再做用户要求的差异。读 [货轮基准](references/ocean-baseline.md)。
- **新模拟器**：复用输入、命名、播放、相机、录屏及演示编排。先定义该场景的主体、环境、状态和动力学，再实现适配器。读 [接口与扩展](references/architecture.md)。
- **已有项目改进**：先检查现有引擎及边界，只引入缺少的模块，不用基线覆盖项目。

不要把船名、海浪、日月、18 节航速或固定四个预设变成所有模拟器的要求。轨道需要引力与时间尺度，机械需要机构约束；名称替换不能代替模型实现。环境模块按场景语义启用。

## 启动可复现基线

在空目标目录执行；把 `<skill-dir>` 换成本 skill 的实际绝对路径：

```sh
node "<skill-dir>/scripts/scaffold.mjs" "<target-project>"
cd "<target-project>"
npm ci
npm test
npm run dev
```

默认 `/?scene=cargo`，海洋实验室为 `/?scene=ocean`。保留 lockfile；依赖升级作为单独变更。`node "<skill-dir>/scripts/scaffold.mjs" --verify` 校验随附源码与效果证据的 SHA-256。脚本拒绝覆盖非空目录；已有项目按模块合并。

## 实现时保持的约束

1. 一个明确的场景状态驱动 UI、渲染、动力学和演示。实际速度、目标速度、模拟时间与墙钟时间分开。界面使用用户可理解的单位。
2. 主体可选择、拖动或按场景合理方式操纵；空白区域保留镜头操作。物体拖动结束恢复镜头，切换主体或预设后仍能找回主体。
3. 镜头预设只提供初始构图。自由模式不能在每帧被 `lookAt` 或位置赋值抢回控制；明确的驾驶台附着模式可例外，但要可退出。主体移动时镜头位置和焦点保持一致的跟随位移。视角切换处理阻尼残留、FOV 和俯仰限制。
4. 名称更新真实模型标识、界面及导出字幕，支持中文并限定长度；按项目 / 场景存储，不携带基线浏览器中的个人偏好。
5. 可暂停、继续、重置；参数改变有可见且连续的作用。运动产生的轨迹保存在世界坐标，不能把一张贴图绑在主体后面冒充历史。
6. 录屏区分实时捕获与逐帧导出。实时使用 GPU canvas captureStream，避免每帧同步回读；不能承诺实际帧率。自动演示用固定步长推进模拟，并等待编码背压，每帧赋予准确时间戳，不能复制低帧率画面来凑 30fps。
7. 演示章节随场景能力生成，覆盖主要操作及环境变化；结束、中断或错误时恢复参数、主体、相机、时间及暂停状态，清理编码器、流、纹理与监听器。重置可复算缓存，不必复制巨大的 GPU 高度场。

新主体的几何、材料、运动及响应需要单独设计；复用成熟框架并不保证新场景自然达到货轮效果。

## 参考图与视频

用户给参考视频时，先检查整段关键帧及运动连续片段，再记录可观察的差异：尺度、浪脊 / 形变、材质高光、空间雾、主体占比、地平线、镜头轨迹。不要仅凭封面猜实现，也不要声称获得未确认开源的原项目源码。

用当前场景自己的尺度调模型。海洋的几米波浪相对 150 米货轮与几米小艇的观感不同；不要为了相似截图偷偷改变单位含义。做近景与远景过滤，避免规则噪声条纹、远处闪烁和三角形法线块。

## 交付与质量

按 [验收方法](references/quality.md) 检查可见行为；截图和视频证据来自实际运行，不用示意图代替。复现货轮时与随附截图比较构图、材质与功能，允许 GPU、字体及非确定粒子带来小差异，不要求逐像素一致。

跑与变更有关的检查和构建，再做浏览器验证。报告实际通过项、实时性能范围、导出帧数与尚未验证项。参考基线曾导出 45 秒 / 1350 帧 / 30fps；这不是对所有设备或新场景的性能保证。默认交付本地可运行项目；发布和上传另按用户要求执行。
