# 验收方法

## 选择有意义的检查

先保证模型行为和交互，再确认画面、性能与导出。纯 UI 文案无需额外逻辑测试。数值积分、世界坐标轨迹、模拟时钟、异步编码背压、取消与恢复适合单元测试；材质和构图须实际浏览器检查。构建通过不能证明 shader 编译或视频可播放。

## 浏览器验收场景

1. 更改主体名称（含中文）、应用并刷新；模型标识、UI 与新视频名称同步，场景之间不串名。
2. 在每个外部观察预设旋转 / 缩放 / 平移，持续观察确认不被下一帧覆盖。主体拖动后仍可归位。拖动物体不同时旋转相机。
3. 先把镜头偏离，再切预设。主体重新入镜且主要结构未被面板遮挡；日月观测在适用时同时保留光源与主体。对低、正午、夜间光源都检查；相机需允许合理向上看。
4. 调参数、暂停 / 继续、重置；确认场景确有响应。运动轨迹留在原世界位置，停下不生成虚假新轨迹。
5. 结束及中断自动演示，比较前后参数、物体位置、相机 / FOV、模拟时间和暂停状态。导出期间调整窗口尺寸也不改变视频分辨率。
6. 分别录制有声 / 无声，检查预览播放、下载、尺寸、时长；无声分支不带音轨。每轮不必穷举所有分辨率，改动尺寸处理时再覆盖对应分支。

浏览器不可读时如实记录阻碍。可以继续代码与单元验证，但不把旧截图、原片或纯构建结果冒充新版本视觉验收。

## 帧率与视频证据

实时帧率在页面可见且负载稳定时测，注明 GPU、分辨率、pixel ratio 和可见性；不要把后台限帧判成 shader 本身耗时，也不能只测 JS 提交时间代表 GPU 总耗时。

45 秒 / 30fps 的自动导出应有 1350 帧。用实际新视频检查：

```sh
ffprobe -v error -select_streams v:0 -show_entries stream=codec_name,width,height,r_frame_rate,avg_frame_rate,nb_frames,duration -of json output.mp4
ffmpeg -v error -i output.mp4 -fps_mode passthrough -enc_time_base:v 1:1000000 -f null -
```

除元数据外检查一段动态片段的连续帧，避免只复制图片凑 fps。基线导出已验证前 90 帧各不相同；暂停章节或静态场景可有合理重复，不能把“所有帧必须不同”当通用断言。取多个章节关键帧确认主体、环境、镜头与字幕确实变化。

无 ffmpeg 时先用浏览器元数据、实际播放及编码时间戳计数验证，明确未做的检查，不为验收自动安装系统软件。

## 参考视频对照

本地视频可用 ffprobe 读时长，再以 ffmpeg 采样整个视频并检查连续运动段。抓图后实际查看，记录观察到的内容。保留用户原文件，证据输出到项目 artifacts；不要把外部参考素材打包成自己生成的模板资产。

交付一份新截图与有代表性的导出样片，说明实现了什么、验证了什么及剩余边界；不把旧记录中的“通过”继承给修改后的项目。
